# GregScope 0.2.0

Machine Sensors, the Telemetry Hub and 24 hours of history, for GTNH 2.9.0-beta-3.

> **Breaking: the client now needs GregScope.** v0.1 was server-only. The Telemetry Hub has a GUI, so from 0.2.0
> every connecting client needs the mod at the **same version**. A client without it, or on a different version, is
> refused at the FML handshake with a message saying so.

### Added

- **Machine Sensor** (GT cover, assembler at MV). Place it on a GT basic machine or a multiblock controller and
  GregScope records that machine. Each sensor has a UUID stored in the cover's own NBT, so its identity and history
  survive the machine being broken and replaced, a chunk unload, and a server restart. Optional label, set in an
  anvil before placing, with `/gregscope label`, or in the Hub.
- **Telemetry Hub** (block, assembler at EV). A GUI listing every sensor its owner can see, worst first, with a
  detail panel, a Problems filter, paging, and 5-minute and 24-hour summaries with an hourly uptime strip.
- **History.** 24 hours of one-minute samples per sensor, in a fixed 92,224 B file under `<world>/gregscope/`.
  Per-minute state breakdown, EU/t average, minimum and maximum, buffered energy, completed recipes and the reason
  for every gap. The format is documented byte for byte in
  [docs/history-format-v1.md](https://github.com/Ldogg123/gregscope/blob/master/docs/history-format-v1.md) so the
  data is readable without the mod.
- **Commands.** `/gregscope stats | list | info | label | purge`, each checking its own permission. A sensor you
  cannot see answers exactly as one that does not exist, so the command cannot be used to probe for other players'
  machines.
- **OpenComputers.** `getSensor` and `getSensorHistory` on the existing machine component, plus a new
  `gregscope_hub` component with `getInfo`, `listSensors`, `getLatest` and `getSensorHistory`, and an
  [example script](https://github.com/Ldogg123/gregscope/blob/master/docs/examples/gregscope-hub.lua).
- **Access control.** Sensors are visible to their owner, the owner's GTNHLib team, and operators. Renaming can be
  restricted to team officers. Hubs show their *owner's* scope, so opening someone else's Hub never widens your own
  access.
- **Configuration**, `config/gregscope.cfg`: sampling interval and per-tick budget, caps on sensors, per-team
  sensors and open GUIs, history retention and expiry, the I/O queue size, the operator level, and the rename
  cooldown. Every key is documented in
  [docs/sensors-and-hub.md](https://github.com/Ldogg123/gregscope/blob/master/docs/sensors-and-hub.md).
- **Documentation**: a player guide, the history format, and the metrics model that fixes the metric names and
  labels the planned v0.4 Prometheus exporter will use.

### Changed

- The OpenComputers `getSnapshot()` contract and schema v1 are **unchanged**, and Adapter component addresses do not
  change on upgrade. v0.1 scripts keep working.
- v0.1's "no periodic work" guarantee is replaced by a bounded one: one tick handler, a hard per-tick sampling
  budget (`sampling.tickBudgetMicros`, default 1 ms) that defers rather than overruns, and bounded memory and disk
  by construction.

### Security

- The Telemetry Hub's access check and open-view cap are enforced in `buildUI`, not only on the right-click.
  ModularUI2 registers its open-GUI packet client-to-server with client-chosen coordinates, so a modified client
  could otherwise have opened any Hub in the world without touching the block and read another team's sensors.

### Notes

- GregScope still never starts, stops, configures or feeds a machine, and never moves an item or a fluid. It uses no
  mixins, no access transformers and no reflection in shipped code, and it never loads a chunk - all four are
  enforced by tests.
- A face carrying a sensor is excluded from GT's rain checks, so it no longer catches fire or explodes in a
  thunderstorm. This is true of every GT cover and is not something a cover can opt out of; it is called out in the
  player guide because it is a real behaviour change.
